# REPS NOTE

筋トレ・食事・PFC・体重・ボディメイク計画を記録し、共有画像を作るWebアプリです。スマートフォンのブラウザーから使えます。[REPS NOTEを開く](https://maca-labs.github.io/repsnote/)

`main` の更新時にGitHub Actionsが構文チェックとテストを実行し、成功すると `dist/` をGitHub Pagesへ公開します。

「食事・PFC」では、選んだ日までの7日間の摂取カロリーを棒グラフで確認できます。「からだ・計画」には体重の推移を表示します。

筋トレ・食事画面の日付の横にある「AIへの質問文をコピー」で、選んだ日の完了セット、食事、合計kcal・PFCをまとめてコピーできます。その日の体重や有効な目標も、記録があれば含めます。相談したいAIの入力欄に貼り付けて使います。

トレーニングの共有画像と投稿文には、選んだ日に自己ベストを更新した種目数が表示されます。前日までの最高重量を超えた種目を数え、自重種目では同じ追加重量での回数更新も含めます。初めて記録した種目は集計対象外です。

「履歴」で月を選び、「月間まとめをシェア」を押すと、その月のトレーニング日数・筋トレの完了セット数・自己ベスト更新種目数を画像や投稿文にできます。同じ種目が月内に何度更新しても1種目です。有酸素の時間や食事を記録した日の平均摂取カロリーも表示します。「重量・体重を表示」をオンにすると、総ボリュームと記録した体重を載せられます。

「種目を追加」→「有酸素」では、ウォーキングやランニング、エアロバイクなどを選べます。時間（分）に加えて、距離（km）・傾斜（%）・速度（km/h）・消費カロリー（kcal）・歩数を任意で記録できます。有酸素の消費カロリーは食事の摂取カロリーと別に保存します。

## メニューと種目の編集

「メニューを選ぶ」の鉛筆ボタンから、PUSHなどの既定メニューと自作メニューの両方を編集できます。名前・説明・種目の追加、削除、並べ替えに対応します。編集画面でメニュー自体を削除しても、すでに記録したトレーニングは残ります。

種目カードの「…」→「種目名・部位を編集」で、名前とカテゴリを変更できます。同じ種目の過去の記録・自己ベスト・メニューの表示も一緒に更新されます。重量の単位や種目別の休憩設定はそのまま使えます。

## 記録を取り込む

「設定・バックアップ」→「筋トレ記録を取り込む」で、CSV／TSVを選ぶか表を貼り付けます。元の種目名ごとにREPS NOTEの種目を選び、取り込まない種目は除外できます。プレビューでは全セットを20件ずつ確認できます。元の記録と照合してから「記録に追加」を押します。日付・種目名・重量・回数を含む最小例です。

```csv
日付,種目,重量(kg),回数
2026-11-01,ベンチ,40,10
2026-11-01,ベンチ,42.5,8
```

単位を省いた重量はkg、完了欄を省いたセットは完了済みになります。セット数・lbs・ウォームアップ・補助・RPEと、有酸素の時間・距離なども扱えます。重複は日付と取込先の種目内で照合します。REPS NOTEのセット履歴CSVは読み戻せます。外部アプリの専用バックアップには、その形式に応じた変換が必要です。

Android版「筋トレMEMO」の暗号化バックアップZIPを選ぶと、形式を確認して案内を表示します。暗号化されたデータベースからセットの値を読み出す機能はありません。記録画面が見られる場合は、取込画面から転記用の質問文をコピーし、スクリーンショットや共有文と一緒に自分で選んだAIへ渡せます。返答の表を貼り付け、元画面と日付・重量・回数を照合してから取り込みます。

「食事・PFC」→「AIから一括取込」で、食べたものを書き、検索依頼文をコピーして検索できるAIに渡します。返ってきたJSONを貼り付けると、食品ごとに出典・推定表示・kcal・PFC・食べた量を確認、訂正できます。倍率を選ぶと摂取量と合計が変わります。不明な値は入力するか、その食品を外してから選択日の記録に追加します。

## ホーム画面に追加

初回訪問時の「インストール」、または「設定・バックアップ」→「アプリのインストール」から追加できます。iPhoneではSafariの「共有」→「ホーム画面に追加」→「追加」を選びます。初回の案内を表示したことは、ブラウザーごとに記憶します。

オンラインで一度開き、アプリのファイルの保存が完了すると、オフラインでも起動して記録できます。

## 起動

Node.js 20以上を使い、このフォルダで次を実行します。
外部パッケージのインストールやAPIキーは不要です。

```sh
npm start
```

ブラウザで `http://127.0.0.1:4173/` を開きます。
HTMLを直接ダブルクリックする `file://` 起動ではES modulesを読み込めないため、HTTPサーバーを使用してください。
ポートを変える場合は環境変数 `REPNOTE_PORT` を指定します。
Pythonがある環境なら `python -m http.server 4173 --directory dist` でも起動できます。

## 確認

```sh
npm run check
npm test
```

`npm test` で `tests/` 内のテストをすべて実行します。単位換算・自己ベスト・栄養計算に加え、入力と復元の整合性、保存失敗、同時編集、日付またぎ、カロリー推移、AI質問文、共有内容を検証します。
画面操作の確認状況と未確認事項は `QA_NOTES.md` に記載しています。

## 保存とプライバシー

- 初回は架空のサンプルを表示します。「自分の記録をはじめる」で空の実記録モードへ切り替えます。
- サンプルと実記録の保存先は別です。
- 書き出したJSONは元のモードで復元してください。サンプル表示中に実記録のバックアップを選ぶと、実記録モードへ切り替えるように案内します。
- 保存に失敗すると直前の記録に戻り、画面に通知が出ます。別タブの更新を検出したときは最新の記録を確認してから再入力してください。
- データはブラウザのlocalStorageに保存します。自動のクラウド同期はありません。
- JSONバックアップにトレーニング、食品、食事、体重、目標、設定を含めます。JSONの復元は置き換え方式です。読み込めるファイルの上限は64MiBです。
- CSVで筋トレと有酸素の履歴を追加・書き出しできます。食品・体重・設定など全記録を移す場合はJSONの書き出し・復元を使います。
- ページのアプリコードから外部APIへ記録を送信する処理はありません。SNS投稿は利用者が端末の共有画面から選択します。
- ブラウザやURLのオリジンが変わると別の保存領域になります。移行前にJSONをバックアップしてください。
- 配布用ZIPにユーザーの実データや認証情報は含めません。

## 現時点の範囲

実際の記録・訂正・共有画像生成を行うフロントエンドの初版です。
ログイン、クラウド同期、食品検索API、バーコード、写真解析は未実装です。食事の一括取込では、利用者が選んだ外部AIで検索できます。
セット表の重量欄と直接入力画面でkg・lbsを種目ごとに選べます。次回も同じ種目には前回選んだ単位を使います。画面上部の切り替えは、単位が未設定の種目と合計ボリュームに適用します。重量の保存単位はkgです。

ダンベルの重量候補は2kg刻みです。lbs表示では同じダンベルの重量を換算して表示します。直接入力と前回の端数重量も選べます。

休憩タイマーの自動開始は初期設定でオフです。「休憩」から手動で開始できます。セット完了時に自動で開始するには、「設定・バックアップ」の「完了したら休憩タイマー」をオンにしてください。
種目名の右の「…」から、その種目で使う休憩時間を秒単位で保存できます。空欄に戻して保存すると標準の休憩時間に戻ります。
休憩タイマーは画面上の表示です。バックグラウンド通知・音・スマートウォッチ連携はありません。
スマートフォン実機のOS共有シート、ファイル保存・ファイル選択は別途確認してください。
